BACKEND — Configuración & Arranque
Variables de entorno validadas Configuración backend/src/config/env.js

Lee las variables del archivo .env y las valida con Zod antes de que cualquier módulo las use. Si falta o es inválida alguna variable obligatoria (DATABASE_URL, JWT_SECRET, CORS_ORIGIN, etc.), el proceso aborta con un mensaje claro. Exporta un objeto con los valores ya tipados y seguros.

Exporta
Objeto <code>env</code> con PORT, NODE_ENV, DATABASE_URL, JWT_SECRET, JWT_EXPIRES_IN, BCRYPT_ROUNDS, CORS_ORIGIN, TRUST_PROXY_HOPS.
Depende de
.env (archivo local, no versionado)
Cliente Prisma compartido Configuración backend/src/config/prisma.js

Crea y exporta una única instancia de PrismaClient que es reutilizada por todos los servicios. Evitar múltiples instancias previene el agotamiento del pool de conexiones.

Exporta
Instancia global de <code>PrismaClient</code>.
Depende de
@prisma/client
Fábrica de la aplicación Express Arranque backend/src/app.js

Crea y configura la aplicación Express: aplica Helmet (cabeceras de seguridad), configura CORS restringido a CORS_ORIGIN, limita el tamaño del body a 100 KB, monta el router principal en /api y registra los middlewares de 404 y manejo de errores.

Exporta
Instancia de Express <code>app</code> (también expone <code>app.createApp</code> para tests).
Depende de
express, helmet, cors, config/env, routes/index, middlewares/*
Punto de entrada HTTP Arranque backend/src/server.js

Llama a app.listen() en el puerto configurado. Es el único archivo que realmente arranca el servidor; app.js solo lo construye. Esto facilita importar la app en tests sin levantar un puerto real.

Exporta
(ninguno — solo efecto de lado: inicia el servidor)
Depende de
config/env, app

Crea usuarios hasheando la contraseña, lista con búsqueda/filtros/paginación, obtiene por ID, actualiza datos y activa/desactiva. Devuelve siempre la proyección adminUser (sin passwordHash ni tokenVersion).

Lógica de estructura académica Service backend/src/services/academic.service.js

CRUD genérico para EducationLevel, Grade, AcademicPeriod y Section, con validaciones de negocio: el orden de un grado debe ser válido para su nivel, las fechas del período deben ser coherentes y no pueden dejar asistencias fuera de rango al modificarse. El update de AcademicPeriod usa una transacción Serializable.

Exporta
<code>{ AcademicError, list, get, create, update }</code>
Depende de
config/prisma
Gestión de perfiles de estudiantes y docentes Service backend/src/services/profile.service.js

Crea, actualiza y lista Student y Teacher. Verifica que el User vinculado exista, esté activo y tenga el rol correcto (ESTUDIANTE o DOCENTE). Todas las escrituras ocurren dentro de transacciones.

Exporta
listStudents, getStudent, createStudent, updateStudent, listTeachers, getTeacher, createTeacher, updateTeacher
Depende de
config/prisma, utils/user, utils/module-error
Gestión de matrículas Service backend/src/services/enrollment.service.js

Crea matrículas verificando que estudiante y sección estén activos y que el estudiante no tenga ya una matrícula en el mismo período. En la transferencia de sección, bloquea el traslado si ya existen notas o asistencias. Resuelve automáticamente el academicPeriodId desde la sección.

Exporta
<code>{ list, get, create, update }</code>
Depende de
config/prisma, utils/module-error
Cursos y asignaciones docentes Service backend/src/services/course-assignment.service.js

CRUD de cursos y de TeachingAssignment. Al crear o reactivar una asignación, verifica que curso, sección y docente estén activos y que el usuario tenga rol DOCENTE. Expone también assignmentEnrollments para listar los alumnos de una asignación con paginación.

Exporta

Registros de notas y asistencia Service backend/src/services/academic-record.service.js

CRUD genérico para GradeRecord y AttendanceRecord. Aplica el scope del usuario (DOCENTE solo ve sus asignaciones, ESTUDIANTE solo sus matrículas). Valida que la asignación y la matrícula pertenezcan a la misma sección y que la fecha de asistencia esté dentro del período académico. Toda escritura ocurre en transacción.

Exporta
<code>{ list, get, create, update }</code>
Depende de
config/prisma, utils/module-error, services/record-access.service, services/course-assignment.service

Determina el "scope" de un usuario para consultar o escribir registros: DOCENTE → su teacherId, ESTUDIANTE → su studentId, ADMIN/SECRETARIA → sin restricción. Provee funciones para construir cláusulas where de Prisma y para verificar que un registro pertenezca al scope del usuario.

Exporta

Depende de
